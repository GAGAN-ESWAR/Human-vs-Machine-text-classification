# CP 219 Project 1: Machine Learning Agent Guidelines & Project Spec

## Overview
This repository contains code for **CP 219: Project 1 (Human vs. Machine Text Classification)**.
The objective is to train a binary classifier that determines whether a tokenized document was authored by a human (label `A`) or generated by a language model (label `B`).

---

## 1. Project Constraints & Rules
- **Task**: Binary sequence classification (`A` = human, `B` = machine).
- **Metric**: Classification Accuracy $\frac{\text{correct}}{\text{total}}$.
- **No External Data**: External datasets, pre-trained language model checkpoints outside allowed tooling, or web scraping to de-obfuscate tokens are strictly prohibited.
- **Vocabulary**: Fixed token IDs in the range `[0, 18437]`. Token `0` denotes rare/unknown words.
- **Data Files**:
  - `train.json`: 10,536 labeled documents (`id`, `text`, `label`).
  - `test.json`: 3,000 unlabelled documents (`id`, `text`).
  - `sample_submission.csv`: Template containing the exact 3,000 IDs and headers.

## 3. Strict Submission Requirements
Whenever writing a script that produces a Kaggle submission:
1. **Format Check**: Must contain exactly two columns: `id, label`.
2. **Row Count**: Must contain exactly 3,001 lines (header line + 3,000 data rows).
3. **ID Order**: Row IDs must match `sample_submission.csv` or `test.json` in the exact original order.
4. **Valid Values**: Predicted labels must strictly be either `A` or `B`.
5. **Sanity Check Function**: Every submission generation script must assert the following:
   ```python
   assert sub.shape == (3000, 2), f"Expected shape (3000, 2), got {sub.shape}"
   assert set(sub.columns) == {"id", "label"}, f"Invalid columns: {sub.columns}"
   assert set(sub["label"].unique()).issubset({"A", "B"}), "Labels contain values other than A/B"
   assert (sub["id"].values == sample_sub["id"].values).all(), "Test IDs do not match sample submission order"
   ```

## 4. Modeling & Validation Workflow
To avoid overfitting the 50% public leaderboard:
- **Local Cross-Validation**: Always use 5-fold Stratified K-Fold cross-validation (`StratifiedKFold(n_splits=5, shuffle=True, random_state=42)`). Never report or rely on a single train-test split.
- **Metrics**: Track Accuracy, along with Precision, Recall, and ROC-AUC for both classes `A` and `B` to monitor class imbalances.
- **Baseline Increments**:
  1. *Baseline 1*: Token n-gram TF-IDF (1-gram to 3-gram) + Logistic Regression / Linear SVM.
  2. *Baseline 2*: Statistical stylometric features (document length, vocabulary richness, token frequency entropy, repetition rates) + LightGBM / XGBoost / CatBoost.
  3. *Baseline 3*: Sequence-level architectures (1D CNN, BiLSTM with embedding layers, or lightweight custom Transformer encoder).
  4. *Ensembling*: Blending/stacking out-of-fold probability predictions.
