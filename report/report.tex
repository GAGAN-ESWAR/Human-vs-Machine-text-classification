% 1. ABSTRACT
% =====================================================================
\begin{abstract}
This report presents a binary classification system for distinguishing human-authored text (Class A) from machine-generated text (Class B), operating on pre-tokenized integer token-ID sequences rather than raw text. The dataset comprises 10,536 training documents and 3,000 test documents over a vocabulary of approximately 18,438 token IDs. Through systematic feature engineering, we developed a 150,027-dimensional feature representation combining TF-IDF n-grams (150,000), extended stylometric statistics (18), class-conditional Markov chain log-likelihoods (8), and a Heaps' Law vocabulary-growth exponent (1). Using LightGBM as the primary classifier, this pipeline achieved \textbf{96.00\% accuracy} on the Kaggle public leaderboard. A noise-floor methodology based on multi-seed cross-validation (CV) with a $2\sigma$ threshold was introduced to prevent submission of statistically insignificant improvements. Systematic testing of six additional feature families confirmed that the champion feature set saturates the available discriminative signal. Two independent pseudo-labeling experiments inflated CV accuracy (to 94.92\% and 94.58\%) but failed on the leaderboard (94.86\% and 95.53\%), providing clear evidence that self-training on high-confidence predictions reinforces existing decision boundaries without improving generalization.
\end{abstract}

\section{Introduction}

The proliferation of Large Language Models (LLMs) capable of producing fluent, coherent text has created an urgent need for reliable detection systems. This project addresses this challenge under a specific constraint: the text is provided as \textbf{pre-tokenized integer sequences} with an unknown tokenizer mapping. No raw words, punctuation marks, sentence boundaries, or pre-trained embeddings are available. All feature engineering must therefore operate directly on integer token-ID sequences.

The objective is to maximize classification accuracy on a held-out Kaggle test set. The competition leaderboard indicates that scores of 97\%+ are achievable, establishing a ceiling above our current result.

The key contributions of this project are:
\begin{enumerate}
    \item A \textbf{150,027-feature pipeline} that combines four complementary signal families (lexical, statistical, generative, information-theoretic) to achieve 96.00\% Kaggle accuracy.
    \item A \textbf{noise-floor methodology} (multi-seed CV with a $2\sigma$ acceptance threshold) that prevented wasted submissions on statistical noise.
    \item \textbf{Systematic negative results} with mechanistic explanations: pseudo-labeling failure (2-for-2), feature saturation evidence, and dimensionality reduction degradation.
    \item A \textbf{memory-efficient Markov chain implementation} using sparse dictionaries instead of dense $V{\times}V$ matrices, enabling class-conditional bigram/trigram log-likelihood computation over a vocabulary of 18,438 tokens.
\end{enumerate}

\textbf{Exploratory Data Analysis (EDA) Observations:}
Human documents are shorter on average ($\mu=138$ tokens, $\sigma=101$) with a tight distribution, while machine documents show a higher mean length ($\mu=213$) but much larger variance ($\sigma=238$). Interestingly, both classes share a very similar median length ($\approx 110$ tokens). Type--token ratios are nearly identical across classes ($\approx 0.64$), suggesting that vocabulary richness \textit{alone} is not discriminative enough. The OOV (Out-Of-Vocabulary) sentinel token (ID~0) appears slightly more in human text (2.7\% vs.\ 1.9\%), reflecting the vocabulary truncation applied during obfuscation. Of the 14,000 unique tokens observed in training, 12,239 appear in the test set with only 157 unseen tokens, confirming adequate vocabulary overlap.

Each document is a variable-length list of integer token IDs. The obfuscation prevents the direct application of linguistic knowledge, pre-trained embeddings, or character-level features. The class imbalance (65:35, Machine:Human) was addressed via \texttt{scale\_pos\_weight} = 1.848 in gradient boosted tree models and \texttt{class\_weight="balanced"} in linear models.

\section{Methodology}

\subsection{Pipeline Architecture}
The classification pipeline extracts four families of features from each document, horizontally stacks them into a single sparse matrix, and feeds the result to a LightGBM classifier:

\begin{verbatim}
Input: Token-ID sequence (List[int])
  │
  ├── TF-IDF Vectorizer (1–3 grams, 150k features, sublinear_tf)  →  Sparse (N × 150,000)
  ├── Extended Stylometric Features (18 features)                 →  Dense  (N × 18)
  ├── Generative Markov Features (8 features)                     →  Dense  (N × 8)
  └── Heaps' Law Exponent (1 feature)                             →  Dense  (N × 1)
  │
  └── scipy.sparse.hstack  →  Sparse Matrix (N × 150,027)
  │
  └── LightGBM Classifier  →  P(Machine)  →  Threshold  →  "A" or "B"
\end{verbatim}

\subsection{Evaluation Protocol}
\begin{itemize}
    \item \textbf{Cross-validation}: 5-Fold Stratified K-Fold (\texttt{shuffle=True}, \texttt{random\_state=42}).
    \item \textbf{Metrics}: Accuracy, Precision, Recall, F1, ROC-AUC (per fold and mean $\pm$ std).
    \item \textbf{Leak-free discipline}: All feature extractors are fit exclusively on the training fold and applied to both train and validation folds. This is enforced by a \texttt{feature\_factory()} pattern in \texttt{cv\_evaluate()}, which creates a fresh instance for each fold.
    \item \textbf{Kaggle submissions}: Limited to 5 per day, which formed the binding constraint on our validation strategy.
\end{itemize}

\subsection{Noise-Floor Methodology}
Local CV accuracy had repeatedly failed to track Kaggle leaderboard performance perfectly. To prevent submission of statistically insignificant improvements, we established a strict noise floor. We ran the Champion model through 5-fold CV with five different random seeds (42, 100, 2026, 777, 12345). We observed $94.15\% \pm 0.12\%$ mean accuracy across seeds. The acceptance threshold was set to mean $+ 2\sigma = \mathbf{94.38\%}$. Any new feature must clear 94.38\% in leak-free CV to be considered a true signal.

\section{Feature Engineering}

\subsection{TF-IDF N-gram Features (150,000 features)}
Token-ID sequences are converted to whitespace-joined strings and vectorized using scikit-learn's \texttt{TfidfVectorizer}:
unigrams through trigrams, capped at 150,000 maximum features, with sublinear TF enabled (\texttt{1 + log(tf)}). 
This captures specific token combinations characteristic of AI vs.\ human text. Sublinear scaling dampens high-frequency tokens, weighting rarer discriminative n-grams heavier. Reducing the vocabulary via chi-squared selection degraded performance, and expanding to 200,000 features provided no measurable improvement.

\subsection{Stylometric Features (18 features)}
Six base statistical features are computed without data-dependent fitting: \texttt{doc\_length}, \texttt{unique\_tokens}, \texttt{type\_token\_ratio}, \texttt{oov\_rate}, \texttt{token\_entropy}, and \texttt{compression\_ratio}. 
Twelve extended features capture additional distributions: bigram entropy, unique bigrams, bigram TTR, positional patterns (head/tail mean token IDs), frequency concentration (top-1 and top-5 sum, hapax rate), and vocabulary ranges (range, Q75, Q25). TF-IDF captures \textit{what} tokens are used, whereas these stylometric features capture \textit{how} the token distribution is structured. Stylometric features alone achieved $\approx$79.66\% CV accuracy.

\subsection{Generative Markov Features (8 features)}
This family produced the single largest accuracy improvement (+4.31 percentage points). We construct class-conditional bigram and trigram Markov chain transition models, computing the log-likelihood of each document under both classes.

\textbf{Implementation}: Transition counts are stored in sparse Python dictionaries. A dense bigram matrix for $V=18,438$ would require ${\sim}1.3$ GB; trigrams would need ${\sim}24$ TB. Dictionaries require merely megabytes.

\textbf{Leave-One-Out (LOO) Correction}: When scoring a training document, its own contribution is subtracted from the transition counts before computing its likelihood, running in $O(\text{len}(\text{doc}))$ to prevent self-memorization. Laplace smoothing ($\alpha=0.1$) was applied.

The features are: \texttt{gen\_ll\_human\_bi}, \texttt{gen\_ll\_ai\_bi}, \texttt{gen\_ll\_diff\_bi} (human minus machine), and their trigram equivalents, plus Zipf slope and mean burstiness. The log-likelihood difference (\texttt{gen\_ll\_diff\_bi}) is extremely discriminative.

\subsection{Heaps' Law Feature (1 feature)}
Heaps' Law describes vocabulary size $V$ relative to document length $N$: $V \propto N^\beta$. 
Humans introduce new vocabulary irregularly (bursts), while LLMs show smoother, more predictable vocabulary growth. We estimate $\beta$ via log-log regression across document sampling points.

\subsection{Features Tested and Rejected}
The following features were tested but failed to clear the 94.38\% threshold: 4th-order quadgrams, token shape statistics, sliding entropy, burstiness metrics, graph topology features, and expanding TF-IDF to 200k. The Champion's 150,027 features effectively saturated the available signal.

\section{Models}

\textbf{LightGBM (Primary)}: Efficient on high-dimensional sparse matrices; histogram-based splitting naturally ignores zero-valued features without explicit dimensionality reduction. 
(500 estimators, \texttt{learning\_rate}=0.05, \texttt{num\_leaves}=63, \texttt{scale\_pos\_weight}=1.848, $L_1/L_2$ reg=0.1). 

\textbf{Linear Models}: Logistic Regression (SAGA solver, $C=1.0$) and Linear SVC (isotonic calibration). Used as strong baselines and meta-learners.

\textbf{XGBoost}: Alternative tree ensemble. Significantly slower than LightGBM on the 150k sparse matrix, resulting in its retirement from later experiments.

\textbf{Stacking Ensemble}: Out-of-fold predictions from Champion LightGBM + Logistic Regression fed into a Logistic Regression meta-learner, optimizing the final classification threshold.

\subsection{Pseudo-Labeling Failures}
Two independent self-training attempts (thresholds $>0.95/<0.05$, and $>0.98/<0.02$) successfully inflated CV accuracy (up to 94.92\% and 94.58\% respectively), but degraded Kaggle performance (94.86\% and 95.53\%). Mechanistically, adding high-confidence predictions back as labels simply deepens the model's confidence on easy examples without improving resolution on ambiguous edge cases.

\section{Conclusion}
This project successfully classified pre-tokenized integer sequences as human or machine-generated, overcoming the lack of raw text or linguistic priors. We developed a 150,027-feature pipeline that achieved 96.00\% accuracy on Kaggle. The most impactful breakthrough was the implementation of memory-efficient, class-conditional Markov chain features (+4.31 pp). A strict noise-floor methodology reliably governed experimentation and rejected features that saturated the signal capacity, while pseudo-labeling proved actively harmful to generalization despite inflating local validation metrics. Ultimately, the fusion of lexical (TF-IDF), statistical (stylometrics), sequential (Markov), and dynamic (Heaps' Law) properties comprehensively encapsulates the structural discrepancy between human cognition and algorithmic sampling.
